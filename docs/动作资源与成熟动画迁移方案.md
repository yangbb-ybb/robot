# 动作资源与成熟动画迁移方案

更新时间：2026-11-25

## 目标

为桌面 3D 交互助手引入更成熟、自然的角色动作，不局限于打招呼。优先覆盖待机、挥手、点头、摇头、思考、开心、摸头回应，以及后续的走路、转身、坐下等动作。

**当前状态：已采用「方向 B — 换自带标准人形骨架的角色」。** 运行时角色为 three.js 官方示例中的 Mixamo 官方角色 `Michelle.glb`，自带标准 65 骨 `mixamorig` 骨架与官方蒙皮，6 个 Mixamo FBX 动作原样挂载、零重定向。全套离屏截图验证：**待机、挥手 8 帧、动作回落、点手、头部跟随、Think/Nod/Happy 全部无撕裂、无黑色缺口，头部始终朝正面**。此前"头扭到背后 + 领口黑色裂口"和"大幅挥手撕裂"两个问题均已根治。

## 推荐使用顺序

1. 优先使用腾讯 HY-Motion 在线或本地流程生成第一批动作；中文提示更容易反复调整。
2. 如果生成结果不理想，再用 Mixamo 选择成熟基础动作（本项目当前采用此路径）。
3. 用 Rokoko 动作替换其中需要更自然重量感的动作，例如 Wave、Happy、惊讶和施法类动作。
4. 用 Quaternius 补充走路、转身、坐下、移动和环境交互动作。
5. **角色侧优先选"自带标准人形骨架 + 官方蒙皮"的模型**（Mixamo 官方角色、VRoid、Ready Player Me），动作可直接挂载，避免自己刷权重。
6. 所有动作进入 Blender 后统一清理：修正 T/A Pose 差异、检查肩肘腕和手指、过滤脚底滑动、修正 Root Motion、统一 FPS、导出为一个包含多个 Action 的 GLB；删除非旋转曲线，避免 FBX 绝对位移把骨架拉散。

## 资源使用边界

用户希望以学习项目为目标，并优先追求自然效果。即使学习用途可以尝试更多资源，也建议保留每个资源的来源和许可记录。对于没有明确许可的动作文件，只用于本地研究和动作分析，不把原始文件提交到仓库、发布包或单独分发；真正进入项目交付版本的动作，优先使用 Mixamo、Rokoko 或 CC0 资源。`Michelle.glb` 取自 three.js 官方示例库，复用时应保留来源说明并以 Mixamo / three.js 当前条款为准。

## 执行记录（按时间）

### 第一轮：Q 版粉发少女 + 程序化手工绑骨（历史，已废弃）

用 `scripts/blender_rig.py` 在旧的 Q 版静态 GLB 上程序化建立三级手臂骨骼（`Root/Body/Head/UpperArm/Forearm/Hand`），按顶点距离场刷权重，手工关键帧生成 `Idle/Wave/WaveLeft/Nod/Shake/Think/Pat/Happy`。

结论：源模型是展示用 A-pose 单壳网格，手臂与躯干焊接、关节无环形拓扑、无指骨；抬臂超过约 40° 袖口即翻出内壁，动作幅度只能压到 ≤20°。此路线无法做出自然的挥手，已放弃。

### 第二轮：Q 版模型 + Mixamo 重定向（历史，已回滚）

`scripts/retarget_mixamo.py` 把下载的 6 个 Mixamo FBX 重定向到 Q 版自定义骨架。核心算法为"仅复制源骨骼世界旋转 + 常量朝向补偿四元数 + 30fps"。

结论：短期画面可用，但旧模型自动权重存在结构性缺陷（肩膀/上胸 100% 绑到 Head、前臂/袖口大量绑到 Root），动作迁移后出现袖口/领口/裙子撕裂。已回滚，并确认**问题出在旧模型拓扑，不是动作本身**。用户据此明确要求放弃 Q 版玩具模型，改用成人比例 3D 建模。

### 第三轮：成人比例模型 + Mixamo 标准骨架（历史，已被第四轮替代）

#### 模型与结论

- 生成方式：腾讯混元 3D 文生模型（`3d`, `--model 3.1`, `--generate-type Normal`, `--enable-pbr`）。
- 源模型：`models/assistant/assistant-adult.glb`（28 MB，88483 顶点，1 mesh / 1 material / 3 textures，无骨骼无动画，A-pose，Z-up，高 1.1724）。约 7.5 头身、粉发、白色合身及膝裙、泡泡袖，成人比例，非 Q 版。
- 绑定脚本：`scripts/rig_adult.py`，最终停在 v12，导出 34.9 MB。

#### 关键技术结论（保留价值，供日后自建角色参考）

1. **绝不改顶点**。早先把 A-pose 顶点抬平成 T-pose，单壳网格没有肩环拓扑，泡袖和胸前被撕碎。改为**在 EDIT 模式把整条手臂链做刚体矩阵变换**对齐到模型 A-pose，使 bind pose 恰好等于模型原始姿态。
2. **骨架整体缩放烘焙** `s = model_h / skel_h = 0.64055`，消除成人骨架与生成模型的比例失配。
3. **零补偿**：`B_new = M·B_orig`；加 Shoulder 补偿四元数 K 会把头发和泡袖甩成翅膀。代价是所有手势整体带约 64.2° 抬臂偏置。
4. **rotation-only 动画通道**。Mixamo FBX 每根骨骼都写绝对 location/scale，Hips 动画值 0.2852 与静态 0.6679 冲突会让模型散架。先删 Action 非旋转曲线，再在导出后处理 GLB JSON，只保留 `path == 'rotation'` 的通道。
5. **Idle = static hold**：零补偿下 Mixamo Idle 会把双臂抬到胸前，故把 Idle 全部旋转曲线置为单位四元数。
6. **动作阻尼** `damp_arm_rotations`：`Wave` 保留 0.68，其余 clip 0.32。
7. **解析距离场权重 + 区域门控 `arm_mask`**：Blender bone heat 在 88483 顶点单壳网格上失败（`failed to find solution`），改用 20 根 MAIN 骨骼的线段距离场（排除 Shoulder），falloff 0.108~0.15，每顶点最多 4 个骨骼，fallback 2160 个顶点。

#### 迭代表与失败结论

| 版本 | 改动 | 结果 |
| --- | --- | --- |
| v11 | 全抑制 `z>0.78` 的手臂权重 | 待机干净，但动作时袖口黑色缺口、裙面肤色尖片 |
| v12 | 重写 `arm_mask` 为区域门控 | 待机、Think、Nod、Happy、点手、头部跟随干净；挥手仍剩少量缺陷 |
| v13 | 追加 2 轮权重拉普拉斯平滑 | **失败并回滚**：脸部撕裂、腿/鞋裂纹、裙面破洞 |

诊断 v11 时发现 2704 个躯干/腋下顶点被 `Arm` 骨骼主导（样本 `(0.134, 0.028, 0.748)`，权重仅 0.39~0.42），手臂抬起时被拉出身体形成裙面尖片；`arm_mask` 同时饿死泡袖的手臂权重，袖子不随手臂转导致袖口黑洞。v12 修复了大部分，v13 证明继续叠加平滑会破坏表面连续性。

#### 放弃原因

**根因是文生 3D 单壳网格的拓扑**：手臂、泡袖、躯干、裙子、头发焊接在同一网格且无肩环/袖口环拓扑，大幅抬臂时必然出现局部翻面与孤立顶点错位，解析权重无法 100% 消除。用户截图反馈"头也太奇怪了吧"（头部扭到背后 + 领口黑色裂口），随后明确选择 **方向 B：换自带标准人形骨架的角色**，本轮模型退役。

### 第四轮：Mixamo 官方自带骨架角色（当前版本 ✅）

#### 决策依据

用户截图显示头部扭到背后、领口一道黑色裂口；除模型拓扑外，还定位到前端**头部跟随的累积旋转 bug**（见下）。两者叠加导致画面崩坏。用户选择 B 方案：不再自己刷权重，改用出厂即带标准人形骨架与官方蒙皮的角色。

#### 前端适配 `public/index.html`

换角色后有 4 处必须改动，其中第 1 条是踩过的坑：

1. **删除 `Box3.setFromObject` 归一化**。它对 `SkinnedMesh` 返回的是未蒙皮的 bind-pose 包围盒（仅 0.0166 m），按此把模型放大约 70 倍会彻底破坏 skin 绑定，画面只剩一双鞋。官方 GLB 的顶点/骨骼/根节点缩放本身就一致，**不要归一化**。
2. **相机取景适配**：Michelle 身高约 1.66 m（旧模型 1.17 m），改为 `camera.position.set(0, 0.95, 3.35)`、`controls.target.set(0, 0.82, 0)`，FOV 仍为 34°，保证头顶和脚完整入镜。
3. **按骨骼名查找头/手骨**：glTF 导出后 Mixamo 名去掉冒号（`mixamorig:Head` → `mixamorigHead`），用正则 `/^(mixamorig)?Head$/i` 等兼容匹配，得到 `headBone / leftHandBone / rightHandBone`。
4. **点手判定改为屏幕空间投影**：`handScreen()` 把手骨骼世界坐标 `project(camera)` 换算成视口像素，`handAt()` 只比较点击位置与投影点的距离（`rect.height * 0.075`），**不再以 `pickModel()` 射线命中做前置判断**（待机手臂微摆会让点手时灵时不灵），也完全不依赖 3D 单位。

#### 关键 Bug 修复：头部跟随的累积旋转

用户截图里"头扭到背后"的主因之一，是旧代码每帧把 `headBone.quaternion` **当作静息姿态再叠加 look 旋转**：当某个 clip 没有 Head 通道时，`AnimationMixer` 不会覆盖该值，于是每帧的旋转被累加，头部越拧越歪最终转到背面，领口随之撕出黑色裂口。

修法（在渲染循环中，顺序必须严格）：

```text
undoLook()      // 撤销上一帧施加的 look（premultiply 其逆）
mixer.update()  // 让动画写入干净的骨骼姿态
applyLook()     // 基于干净姿态叠加本帧 look，并记住 _appliedLook
```

`applyLook()` 中 yaw/pitch 分别钳制在 ±0.26 / ±0.16 rad，并在动作播放期间把跟随强度降到 0.45，避免和动作自身的头部旋转打架。世界空间的 look 旋转需换算到父骨骼局部空间：`parentQ⁻¹ · R · parentQ`。

## 2026-11-26 UI 切换与模型取景同步

用户反馈模型和聊天窗口/机器人悬浮模式切换不合拍。根因不是模型资源，而是普通窗口与 360×400 悬浮窗口共用了同一套 Three.js 相机位置和目标点；模式切换时 CSS 先改变布局，窗口尺寸随后变化，renderer 又只在下一帧适配，导致模型大小、位置和气泡/UI 短暂错位。

已在 `public/index.html` 增加 `applyCameraLayout()`：普通模式使用原取景，悬浮模式拉远相机至约 4.85，并将目标点略上移；`applyMode()` 使用两帧 `requestAnimationFrame` 等待 CSS/窗口布局完成后再调用 `resize()` 和 `controls.update()`。这样模型取景、透明悬浮窗口和 UI 会在同一轮布局后同步。
